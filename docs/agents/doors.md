# Birdplane merge doors

Proposed policy for Daniel's review in BIRD-34. The merge skill reads door rules
and opt-in from the refreshed default branch, `origin/birdplane`, never from a PR
head. Rules and opt-in below become effective only after Daniel reviews and
merges them. They cannot authorize this migration PR: it always uses **evidence**
mode, and **Daniel reviews and merges** it. Repository settings and green
required checks remain separate gates; this file does not establish them.

The proposed G8 opt-in for later PRs is:

auto-merge: enabled

| Path or changed behavior                                                                                                                                                                                                                                               | Door and reason                                                                                                                                                                                                                                                                                                                |
| ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `apps/api/plane/db/migrations/**`, `apps/api/plane/recurrence/migrations/**`; schema migrations, backfills, or changes rewriting persisted workflow data                                                                                                               | **One-way**: database/data boundary. Changing future project defaults does not authorize rewriting existing projects.                                                                                                                                                                                                          |
| `apps/api/plane/authentication/**`, `apps/api/plane/app/permissions/**`, `apps/api/plane/api/middleware/api_authentication.py`, `apps/api/plane/utils/permissions/**`; API/session authentication and authorization                                                    | **One-way**: auth/permissions boundary. Include permission behavior implemented elsewhere.                                                                                                                                                                                                                                     |
| `apps/mcp/sikku/server.py` HTTP bearer/host handling; `apps/mcp/sikku/plane.py` account/permission scope                                                                                                                                                               | **One-way** when changing auth, trust, or permission behavior; judge mixed modules by changed behavior. Bearer holders share one configured Plane account.                                                                                                                                                                     |
| `apps/api/plane/app/serializers/webhook.py`, `apps/api/plane/db/models/webhook.py`, `apps/api/plane/utils/ip_address.py`, `apps/api/plane/utils/url_security.py`, `apps/api/plane/bgtasks/webhook_task.py`, and `apps/api/plane/settings/common.py` webhook allowlists | **One-way** for webhook destination trust, SSRF defenses, HMAC, secrets or allowlist changes. A local/private target remains a trust decision.                                                                                                                                                                                 |
| Public API/MCP contracts used by other apps                                                                                                                                                                                                                            | **One-way**: external compatibility boundary, including schema/behavior changes outside the listed modules.                                                                                                                                                                                                                    |
| `deployments/birdplane/compose.yml`, `backend.override.yml` in that directory, production Docker/image/env/deploy changes and release actions                                                                                                                          | **One-way**: production configuration and storage. The Compose file mounts external production volumes.                                                                                                                                                                                                                        |
| Push/merge to release branch `birdplane`                                                                                                                                                                                                                               | **Production trigger**: the [Git deployment contract](../../deployments/birdplane/git-compose.md) records Auto Deploy on release pushes. Production-affecting changes require one-way review even for a small source diff. Docs-only extraction remains two-way when its resulting deployment does not alter runtime behavior. |
| Destructive cleanup, restoring over live writes, deleting volumes or records, object-storage rollback                                                                                                                                                                  | **One-way**: code revert cannot restore lost data; production data operations need separately scoped authority.                                                                                                                                                                                                                |
| Owned isolated preview/test container lifecycle                                                                                                                                                                                                                        | **Two-way only** with functional verification and a revert that undoes the change. Never include external production volumes or blanket-classify a module as reversible.                                                                                                                                                       |
| Docs extraction/routing, reversible test/check wrappers, AGENTS and Kitchen guidance                                                                                                                                                                                   | **Two-way** when reverting restores behavior; preserve upstream ownership, licenses and product assets. Verification requirements still apply.                                                                                                                                                                                 |
| Secrets, paid services/plan changes or other spend                                                                                                                                                                                                                     | **One-way**, including when changed outside these paths. Merge permission does not authorize secrets/data/spend operations.                                                                                                                                                                                                    |

Strictest changed behavior wins. Unknown or doubtful blast radius upgrades to
one-way; judgment never downgrades a forced one-way rule. The author states door
and blast radius; the cross-family reviewer confirms or upgrades it. Use
[verification](verify.md) for applicable same-commit receipts and
[GitHub targeting](fork-github.md) for the fork's actual base/checks. No absent or
path-skipped CI lane counts as green. These documentation rules do not activate
GitHub auto-merge or change repository protection.
